API de Wali

Conecta tus otros sistemas con Wali. Lee las conversaciones y los contactos de tu CRM y haz acciones como asignar conversaciones en lote, cambiar la etapa o poner etiquetas.

Todas las llamadas van a esta dirección, con tu clave en la cabecera Authorization.

https://walicrm.com/crm/api/v1
curl https://walicrm.com/crm/api/v1/yo \
  -H "Authorization: Bearer wali_live_TU_CLAVE"

Claves y permisos

Un administrador crea las claves en Ajustes del CRM › API. La clave se muestra completa una sola vez. Guárdala en el sistema que la va a usar.

  • Cada clave ve solo su espacio de trabajo y nunca toca pagos ni la cuenta. De los ajustes, solo enciende o apaga flujos y agentes de IA y cambia el horario de atención.
  • Solo lectura. Lee todo lo de esta página que empieza con GET.
  • Lectura y acciones. Además asigna, cambia la etapa, pone etiquetas, finaliza, crea o edita contactos, enciende o apaga flujos y agentes de IA y cambia el horario de atención.
  • Las acciones se hacen en nombre del administrador que creó la clave, con las mismas reglas que en la pantalla, y quedan registradas.
  • La clave deja de funcionar si la revocas, si vence o si quien la creó ya no es administrador del espacio.
Nunca pongas la clave en una página web ni en una app que se instale en el celular de otra persona. Úsala solo desde tu servidor.

Límites y errores

Hasta 120 llamadas por minuto por clave. Cada respuesta trae las cabeceras RateLimit-Remaining y RateLimit-Reset. Si pasas el límite, la respuesta es 429. Espera los segundos que indica Retry-After.

CódigoQué pasó
400Faltan datos o tienen otra forma. El campo detalle dice cuál.
401La clave no es válida, venció o fue revocada.
403La clave es de solo lectura, o el plan del espacio no está activo (queda en solo lectura).
404Eso no existe en este espacio.
409Alguien cambió lo mismo en el CRM al mismo tiempo. Vuelve a intentarlo.
429Pasaste el límite de llamadas por minuto.

Los errores llegan como { "error": "…" } y las respuestas buenas como { "data": … }.

Páginas

Las listas devuelven hasta 50 elementos (máximo 100 con limite). Si hay más, la respuesta trae siguiente. Pásalo como cursor para pedir la página que sigue.

GET /conversaciones?limite=100
GET /conversaciones?limite=100&cursor=4521

Conversaciones

GET/conversacionesLectura

Filtros: estado (abiertas, pendientes o finalizadas), asignado (id del miembro, o nadie), equipo, etapa, desde y hasta (fechas ISO, por última actividad).

curl "https://walicrm.com/crm/api/v1/conversaciones?estado=abiertas&asignado=nadie" \
  -H "Authorization: Bearer wali_live_TU_CLAVE"
{ "data": [ { "id": 4521, "estado": "abiertas", "canal": "wa", "asignadoId": null, "equipo": "Ventas",
    "contacto": { "id": 812, "nombre": "Laura Gómez", "telefono": "+573000000000", "etapa": "Caliente", "etiquetas": ["Referido"] },
    "ultimoMensaje": "2026-11-11T15:02:11.000Z", "creada": "2026-11-10T21:40:00.000Z" } ],
  "siguiente": 4519 }
GET/conversaciones/:idLectura
GET/conversaciones/:id/mensajesLectura

Del más nuevo al más viejo. Cada mensaje trae tipo (in, out, note…), texto, archivo si tiene, autorId y en.

PATCH/conversaciones/:idAcciones

Manda solo lo que cambias: etapa, etiquetas (agregar y quitar), estado con su motivo, miembroId o equipo.

curl -X PATCH https://walicrm.com/crm/api/v1/conversaciones/4521 \
  -H "Authorization: Bearer wali_live_TU_CLAVE" -H "Content-Type: application/json" \
  -d '{ "etapa": "Pagado", "etiquetas": { "agregar": ["Cliente frecuente"] } }'

Asignar en lote

POST/conversaciones/asignarAcciones

Hasta 100 conversaciones por llamada. Manda miembroId (o null para dejarlas sin asignar), equipo, o los dos. Cada una pasa por las mismas reglas que en la pantalla. Las que no se pueden asignar vuelven en errores con su motivo.

curl -X POST https://walicrm.com/crm/api/v1/conversaciones/asignar \
  -H "Authorization: Bearer wali_live_TU_CLAVE" -H "Content-Type: application/json" \
  -d '{ "conversaciones": [4521, 4519, 4510], "miembroId": "ID_DEL_MIEMBRO" }'
{ "data": { "asignadas": [4521, 4519], "errores": [ { "id": 4510, "error": "…" } ] } }

Contactos

GET/contactosLectura

Filtros: q (nombre, teléfono o correo), etapa y etiqueta.

GET/contactos/:idLectura
POST/contactosAcciones
PATCH/contactos/:idAcciones

Campos: nombre, telefono (con el indicativo del país), correo, etapa y etiquetas. Para crear hace falta teléfono o correo.

curl -X POST https://walicrm.com/crm/api/v1/contactos \
  -H "Authorization: Bearer wali_live_TU_CLAVE" -H "Content-Type: application/json" \
  -d '{ "nombre": "Camilo Torres", "telefono": "+573000000000", "etapa": "Nuevo lead" }'

Para saber qué valores usar en los filtros y en las acciones.

RutaQué trae

Flujos y agentes de IA

Lee los flujos automáticos y los agentes de IA del espacio, y enciéndelos o apágalos. Por ejemplo, apaga el agente fuera de una campaña y vuelve a encenderlo después. Crearlos o editarlos se hace en el CRM.

GET/flujosLectura
{ "data": [ { "id": "bienvenida", "nombre": "Bienvenida", "encendido": true, "cuando": "nueva", "equipos": null } ] }
PATCH/flujos/:idAcciones
GET/agentesLectura
{ "data": [ { "id": "ag_1", "nombre": "Sofía", "encendido": false, "estado": "pausado", "canales": ["wa"] } ] }
PATCH/agentes/:idAcciones

Manda encendido en true o false. Para encender un agente, el espacio necesita un canal conectado y el agente, un canal marcado en «Dónde atiende». Si alguien cambia lo mismo en el CRM en ese momento, la respuesta es 409. Vuelve a intentarlo.

curl -X PATCH https://walicrm.com/crm/api/v1/agentes/ag_1   -H "Authorization: Bearer wali_live_TU_CLAVE" -H "Content-Type: application/json"   -d '{ "encendido": true }'

Horario de atención

El mismo de Ajustes del CRM › Horario de atención. Son los turnos con sus días, horas, almuerzo y las personas que los trabajan, más los festivos y el mensaje que le llega al cliente cuando escribe fuera de horario. El horario de la empresa se arma solo con los turnos, desde la primera hora hasta la última de cada día. De ese horario dependen el aviso fuera de horario, el agente de IA y el chat de la web. Solo lo cambia una clave creada por un administrador o un líder.

GET/horarioLectura
{ "data": { "turnos": [ { "id": "t1", "nombre": "Mañana", "color": "#3B82F6", "dias": [ { "dia": "lunes", "desde": "7:00", "hasta": "15:00", "almuerzo": { "desde": "12:00", "hasta": "13:00" } } ], "personas": ["usr_1"] } ],
  "horarioEmpresa": [ { "dia": "Lunes", "abierto": true, "desde": "7:00", "hasta": "15:00" } ],
  "festivosComoDomingo": true, "mensajeFueraDeHorario": "Estamos fuera de horario…", "dentroDeHorarioAhora": true } }
PATCH/horarioAcciones

Manda solo lo que cambia, ya sea turnos (la lista completa, que reemplaza la de hoy), festivosComoDomingo o mensajeFueraDeHorario. Los días van como lunes, martes, miercoles, jueves, viernes, sabado o domingo, y las horas como 7:00 o 18:30. Las personas son los id de GET /miembros. Para conservar el color de un turno, manda su id. Si alguien cambia el horario en el CRM en ese momento, la respuesta es 409. Vuelve a intentarlo.

curl -X PATCH https://walicrm.com/crm/api/v1/horario   -H "Authorization: Bearer wali_live_TU_CLAVE" -H "Content-Type: application/json"   -d '{ "mensajeFueraDeHorario": "Hoy atendemos hasta las 4 p. m." }'

Webhooks

Wali le avisa a tu sistema cuando pasa algo en tu espacio, sin que tengas que preguntar. Un administrador crea el webhook en Ajustes del CRM › API con la dirección de tu sistema (https) y los eventos que quieres recibir.

EventoCuándo llega
mensaje.recibidoUn cliente escribió.
conversacion.asignadaLa conversación cambió de persona o de equipo. Trae cómo estaba antes.
conversacion.finalizadaAlguien finalizó la conversación.
conversacion.etapaEl contacto cambió de etapa del embudo.
contacto.creadoEntró un contacto nuevo, por un canal o creado a mano.

Cada aviso llega por POST con este cuerpo. El id sirve para no procesar dos veces el mismo aviso.

{ "id": "5f1c…", "evento": "conversacion.asignada", "creado": "2026-11-11T15:02:11.000Z", "espacio": "…",
  "data": { "conversacion": { "id": 4521, "asignadoId": "…", "equipo": "Ventas", "estado": "abiertas", "etapa": "Caliente", "contactoId": 812 },
            "antes": { "asignadoId": null, "equipo": "Ventas" } } }

Responde con un código 2xx en menos de 10 segundos. Si no, Wali lo reintenta a 1, 5, 30, 120 y 360 minutos. Tras 20 fallas seguidas el webhook se pausa y se reactiva desde Ajustes del CRM › API.

Comprueba que viene de Wali. Cada aviso trae la cabecera Wali-Firma con la hora (t) y la firma (v1): HMAC-SHA256 de t.cuerpo con el secreto del webhook, que se muestra una sola vez al crearlo.

// Node.js
const [t, v1] = req.headers['wali-firma'].split(',').map(p => p.split('=')[1])
const esperada = crypto.createHmac('sha256', SECRETO).update(t + '.' + cuerpoCrudo).digest('hex')
const valida = crypto.timingSafeEqual(Buffer.from(v1), Buffer.from(esperada)) && Math.abs(Date.now() / 1000 - Number(t)) < 300
